# add-reference

인자로 받은 URL마다 느낌 노트를 만든다: $ARGUMENTS

인자가 비어 있으면 사용자의 말에서 URL을 찾는다. URL이 없으면 어떤 사이트인지 묻는다.

라이브러리 폴더는 이 스킬 기준 폴더의 `../web-design/library/references/`다. 노트 형식은 그 폴더의 `_template.md`를 따른다.

## 할 일 (URL마다)

1. `index.md`에 같은 URL이 이미 있으면 건너뛰고, 다시 분석하려면 `/webcraft:refresh-references`를 쓰라고 알린다.
2. 브라우저 도구로 사이트를 연다. 단순 페이지 가져오기는 막히는 사이트가 많으니 실제 브라우저를 쓴다. 브라우저 도구가 없으면 멈추고 그렇다고 알린다. 보지 않은 사이트의 노트는 쓰지 않는다.
3. 데스크톱 너비에서 첫 화면을 보고, 끝까지 천천히 스크롤하며 본다. 호버와 모션도 확인한다. 가능하면 모바일 너비도 본다.
4. **수치를 잰다.** 먼저 `node ../web-design/scripts/probe-run.mjs <URL> <스크래치 폴더>/<id>`를 실행한다 (Bash, 백그라운드 가능, 1~2분). 화면 없는 Chrome이 measure.js와 interact-probe.js를 붙여 넣지 않고 실행해 결과 줄을 출력하고, `<id>-top/mid/low/mobile.jpg` 스크린샷을 남긴다. 결과 줄을 그대로 노트에 넣고, 스크린샷으로 3단계 화면 보기를 대신한다 (호버와 모션은 필요하면 브라우저 도구로 따로 본다). 여러 사이트는 동시에 돌려도 된다. 첫 줄이 "화면이 거의 안 그려짐"이거나, 입장 화면·쿠키 창·봇 차단으로 스크린샷이 비면 아래 브라우저 도구 방식으로 잰다. 브라우저 도구로 잴 때는: 창을 1440px로 맞추고 첫 화면에서 `../web-design/scripts/measure.js`의 내용을 브라우저의 JavaScript 실행 도구에 넣는다. 돌아온 열 줄 정도를 고치지 말고 그대로 노트의 `## 실측 수치`에 `- `로 시작하는 줄로 넣는다. 첫 줄에 "화면이 거의 안 그려짐"이 나오면 브라우저 창을 앞으로 가져와 다시 잰다. "입장 화면: 있음"이 나오면 그 값은 쓰지 않는다. `../web-design/scripts/gate-pass.js`를 실행해 넘긴 뒤 처음부터 다시 잰다. 못 넘기면 브라우저 도구로 실제 클릭, 키, 휠을 보내 보고, 그래도 안 되면 사용자에게 눌러 달라고 한다. 쿠키 동의, 연령 확인, 로그인은 넘기지 않고 사용자에게 맡긴다. 끝내 못 넘긴 사이트는 노트 비고에 입장 전 값이라고 적는다. 이어서 같은 화면에서 `../web-design/scripts/interact-probe.js`를 실행해 돌아온 "호버(JS)", "커서", "폼", "클릭 탐색" 줄도 그대로 넣는다. 폼은 제출하지 않고, 비밀번호와 카드 칸은 건너뛴다. 메뉴와 탭처럼 안전한 것만 누르고, 링크, 폼, 구매, 로그인, 동의 버튼은 누르지 않는다. 끝나면 페이지를 새로 고친다. "프레임 낮음"은 페이지가 무거운 경우가 많으니, 가벼운 페이지와 번갈아 재서 창 문제인지 가른다. "아래쪽" 줄에 "wheel-probe.js로 잰다"가 나오면 창 스크롤이 없는 사이트다. `../web-design/scripts/wheel-probe.js`를 한 번 실행해 녹화를 켜고, 스크린샷을 찍은 뒤 브라우저 도구의 스크롤 동작으로 실제 휠을 1~2초 간격으로 여덟 번쯤 보내고, 같은 파일을 한 번 더 실행해 돌아온 "휠 탐색" 줄도 그대로 넣는다. 스크립트로 만든 휠은 많은 사이트가 무시한다. "스크롤 없는 앱형 화면"이면 휠을 두 번만 보내 반응이 없는지 확인한다. 첫 화면 제목이 "SVG"나 "이미지"로 나오면 그림으로 된 글자를 잰 값이다. 믿음이 보통이나 낮음이면 스크린샷과 대조한다 (소문자 로고는 실제보다 작게, 두 줄 로고는 두 줄 높이로 나온다). 캔버스 안의 글자는 못 재니, "움직임" 줄에 "화면을 채움"이 나오면 스크린샷을 보고 노트 본문에 적는다. 로딩 화면과 입장 화면이 끝난 뒤에 재고, 스크린샷으로 첫 화면 제목이 실제 제목인지 대조한다.
5. 템플릿대로 노트를 쓴다. 파일 이름(`id`)은 사이트 이름을 소문자와 하이픈으로 (예: `linear-app`).
   - "왜 좋은가"에 가장 공을 들인다. 무엇이 있는지가 아니라 왜 효과적인지를 쓴다
   - 레이아웃, 타이포, 색, 질감의 숫자는 **실측 수치에서 가져온다** ("26px 정도" 대신 "26px, 본문의 2.3배"). 실측에 없는 것만 눈으로 보고 "추정"이라고 적는다
   - 사이트의 문구, 코드, 이미지를 노트에 옮기지 않는다
6. `index.md` 표에 한 줄 추가한다. styles 칸에는 `index.md` 위쪽의 스타일 키만 쓴다. 맞는 키가 없으면 가장 가까운 키를 쓰고 노트에 이유를 적는다.

## 마무리

추가한 노트 목록과 각각의 한 줄 첫인상을 알린다. 열지 못한 URL이 있으면 이유와 함께 알린다.
