# 사용자에게 보여줄 것

## 4단계: 방향 확인 (여기서 멈춘다)
- 비교표 하나: 행은 레이아웃, 타이포, 색, 모션, 질감. 열은 레퍼런스들 (한 칸에 한두 마디)
- 정한 방향 한 문단과 이유. 레퍼런스를 섞어도 된다 (레이아웃은 A, 타이포는 B)
- 팔레트 2개 (색값과 대비 결과)
- 글꼴 조합 2개 (이 사이트의 상황 한 줄과 그래서 고른 이유, 제목, 본문, UI, 숫자마다 영문과 한글 폰트, 출처, 라이선스 주의)
- **글꼴 시안:** 글꼴 이름만 보여 주지 않는다. 사용자는 이름으로 고를 수 없다. 결과물 폴더에 `font-pick.html`을 만들어 연다. 이 사이트에 실제로 쓸 제목, 본문 한 문단, 숫자, 버튼을 조합마다 위아래로 그린다. 고른 두 조합과, 기준으로 "한글 Pretendard + 영문 General Sans"를 함께 둔다. 사용자가 방향 확인을 생략하라고 하면 만들지 않는다. 사이트가 완성된 뒤 고치는 것보다 훨씬 싸다
- 쓸 모션 목록
- 1단계에서 가정한 것
- 검수 모드 (기본 3회, "꼼꼼하게"라고 하면 정밀 모드)
- **구도 스케치** (아래)

사용자가 고르거나 고치라고 하면 반영해서 다시 보여준다.

### 구도 스케치
레퍼런스의 퀄리티는 색과 글꼴보다 **구도와 비율**에서 나온다. 구현 전에 화면을 설계한다. `note`의 레이아웃·타이포·색·질감 수치를 근거로 쓴다.

**콘셉트 한 문장부터.** 이 사이트를 물건이나 장면 하나로 말한다 (예: "암실 줄에 매달려 마르는 인화지"). 아래 모든 것이 이 문장에서 나와야 한다.

**서로 다른 두 안을 보여 준다.** 같은 콘셉트로 A **안정안**(읽기 쉽고 실패가 적음)과 B **과감안**(구도나 시그니처가 한 단계 더 나감). 두 안은 첫 화면 구도와 시그니처 요소가 달라야 한다. 색이나 글꼴만 다른 두 안은 안 된다. 스타일 모범 섹션(`lib.mjs example`)의 배치나 스타일 카드의 "뻔한 버전"을 어느 안에도 쓰지 않는다. 각 안마다 1, 2를 그리고, 3, 4는 고른 안 기준으로 하나만 쓴다.

1. **첫 화면 구도 (1440px).** 입장·로딩 화면이 있으면 그것도 첫 화면이다. "가운데 원과 퍼센트"처럼 어느 사이트에나 붙는 화면이 아니라 콘셉트의 물건이나 장면으로 만든다 (예: 인화지가 현상되며 차오름). 글자 상자 그림으로 그린다. 어디에 무엇이 얼마나 큰지, 빈 곳이 어디인지 보이게.
   ```
   ┌──────────────────────────────────────────────┐
   │ 로고                              메뉴 3개    │
   │                                              │
   │ 제목 2줄 ── 120px, 왼쪽 7열                   │
   │                         ┌──────────────┐     │
   │ 설명 1줄 18px            │ 시그니처 요소 │     │
   │ 버튼 1개                 │ 5열, 화면 70% │     │
   │                         └──────────────┘     │
   └──────────────────────────────────────────────┘
   ```
   375px에서 어떻게 바뀌는지 한 줄.
2. **시그니처 요소 하나.** 사이트를 닫고도 기억날 것 하나 (예: 스크롤하면 사진이 책장처럼 넘어간다, 제목 글자가 커서에 녹는다). 무엇인지, 어떻게 만드는지(레시피 이름이나 "새로 만듦"), 어느 레퍼런스의 어떤 원리에서 왔는지, **콘셉트 문장과 어떻게 이어지는지**. 다른 사이트에 그대로 옮겨도 말이 되는 요소(진행 막대, 커서 따라오는 원, 퍼센트 로딩)는 시그니처가 아니다. 여러 개를 고르지 않는다
3. **섹션별 틀.** 레퍼런스 실측의 "아래쪽" 줄(페이지 길이, 화면별 가장 큰 글자, 배경이 바뀌는 지점)을 리듬의 근거로 쓴다. 표로: 섹션 | 담을 내용 | 틀 | 근거. 틀은 내용에 맞게 고른다 (큰 숫자 하나, 표, 긴 글 한 단, 사진 한 장 꽉 채움, 가로 흐름, 목록). **이웃한 섹션이 같은 틀이면 안 된다.** "작은 라벨 + 제목 + 카드 3개"는 쓰지 않는다
4. **기준 수치.** 그리드(열 수, 바깥 여백), 제목·본문 크기와 그 비율, 섹션 사이 여백, 둥글기, 선 두께. 레퍼런스 수치에서 비율을 가져와 이 사이트에 맞게 정한다

확인할 때 사용자에게 묻는 것은 하나: "A와 B 중 어느 쪽인가요? (섞어도 됩니다)"

## 7단계: 마무리
- 만든 파일과 여는 방법
- 최종 점수, 수정 횟수, 멈춘 이유, `design-log.md` 위치
- 고치지 못하고 남은 문제
- 남은 자리표시 (사용자가 채울 이미지와 문구)
- 확인하지 못한 것 (예: 브라우저가 없어 코드로만 검수함, 탭이 가려져 fps를 못 잼)
