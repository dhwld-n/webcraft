# 검수와 수정 (6단계 세부)

## 모드
- **기본 (최대 3회):** 검수 에이전트는 처음과 마지막에만 띄운다. 에이전트 한 번이 메인의 도구 호출 여러 번보다 비싸다
  - 1회차: `critic`이 채점하고 수정 목록을 준다
  - 2회차: 메인이 목록을 고친 뒤 **직접** 확인한다. 브라우저에서 `audit.js`를 한 번 실행하고(가능하면 크기 1440과 375를 한 번에 묶어서), 고친 항목이 해결됐는지만 본다. 첫 화면은 원본 배율 스크린샷 한 장으로 구도 스케치와 비교한다. 점수는 매기지 않는다
  - 3회차: `critic`이 다시 채점해 최종 점수를 낸다
  - 1회차에 큰 문제가 없으면 작은 문제만 고치고 바로 마무리한다 (에이전트 1번)
- **정밀 (최대 5회, 사용자가 정하면 최대 10회):** 사용자가 "꼼꼼하게", "정밀하게", "끝까지"라고 했거나 회차를 정해 준 경우. 회차마다 검수 패널 `visual-critic`(55점), `type-critic`(10점), `motion-critic`(15점), `usability-critic`(20점)을 **한 메시지에서 동시에** 띄우고 점수를 더한다. 마지막 회차의 `visual-critic`만 모델을 `opus`로 지정해 띄운다 (에이전트 실행 도구의 model 값). 다른 회차와 기본 모드는 모두 기본값(Sonnet)이다. Opus는 사용량을 빨리 써서 기본 검수에 쓰면 마지막 회차가 한도로 끊긴다

## 넘길 것
공통: 결과물 주소(가능하면 로컬 서버), 확인받은 방향(팔레트, 글꼴, 모션 목록), 스타일 카드 경로, 회차(예: 1/3), `design-log.md` 경로, `SKILL_DIR/scripts/audit.js` 경로.
정밀 모드 추가: motion-critic에는 모션 레시피 폴더 경로, usability-critic에는 `contrast.mjs` 경로, type-critic에는 `SKILL_DIR/scripts/type-pair.js`와 `SKILL_DIR/scripts/lib.mjs` 경로.

## 고치기
- "나빠진 것"이 있으면 그것부터 되돌린다
- 구도 스케치와 다르다는 지적은 화면을 스케치 쪽으로 고친다. 스케치 자체가 틀렸다고 판단되면 고치지 말고 사용자에게 묻는다
- 정밀 모드면 네 목록을 합친다: 큰 문제 → 여러 검수자가 같은 곳을 지적한 것 → 배점이 큰 항목 순. 부딪히는 지적은 확인받은 방향에 가까운 쪽을 따르고 기록한다
- 한 회차의 수정은 한 메시지에 몰아서 한다 (파일별 Edit를 묶어 보낸다)

## 회차마다
- `design-log.md`에 덧붙인다
- 사용자에게 한 줄: `검수 1/3 · 74점 · 히어로 여백, 모바일 메뉴 수정` (2회차는 `확인 2/3 · 남은 큰 문제 0개`)

## 멈추는 조건
- 큰 문제가 하나도 없다
- 점수가 두 회차 연속 오르지 않았다 (정밀 모드)
- 최대 회차를 마쳤다

## design-log.md
결과물과 같은 폴더에 처음 검수할 때 만든다. 짧게 쓴다.

```markdown
# 디자인 검수 기록
방향: <한 문단>
스타일: <키> · 팔레트: <이름> · 글꼴: <이름> · 모션: <목록> · 모드: 기본
레퍼런스: <읽은 노트 id, 쉼표로> (없으면 없음)

## 구도 스케치 (확인받은 것)
<첫 화면 상자 그림, 시그니처 요소, 섹션별 틀 표, 기준 수치를 4단계에서 보여준 그대로>

## 1회차 · 71점
- 고친 것: ...
- 남긴 것: <못 고친 것과 이유>
```
