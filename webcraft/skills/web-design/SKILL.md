# web-design

레퍼런스를 베끼지 않는다. 라이브러리의 "느낌"을 비교해 방향을 정하고 새 코드로 구현한다. 이 스킬의 기준 폴더를 `SKILL_DIR`이라 한다. 에이전트에게는 절대 경로로 넘긴다.

**라이브러리 파일을 통째로 읽지 않는다.** `node SKILL_DIR/scripts/lib.mjs`의 짧은 출력을 쓴다.
- `refs <style...>` 레퍼런스 한 줄 목록 · `note <id>` 레퍼런스 핵심
- `fonts <style> [ko|en]` · `fontshare <분류>` · `motion <style>` · `recipe <이름...>` 레시피 코드와 조절값만 · `example <style>` 스타일의 모범 섹션 코드
- 스타일 카드(`library/styles/<키>.md`)는 짧으니 직접 읽는다

라이브러리를 읽지 못하면(권한 거부 등) 일반 지식으로 대신 만들지 말고 멈추고, 그 폴더 읽기 허용이나 `--add-dir <플러그인 폴더>`를 안내한다.

## 흐름

**1. 요청 정리.** 무엇을(업종, 페이지, 섹션), 분위기(사용자 표현 그대로), 브랜드 색·문구, 구현 기술(`package.json`의 프레임워크를 따르고, 없으면 `index.html`·`styles.css`·`main.js`). 빠진 건 묻지 말고 정한 뒤 4단계에서 알린다.

**2. 후보.** `library/styles/`에서 스타일 카드 1개(없으면 일반 지식으로 하고 알린다). `lib.mjs refs <style>`로 레퍼런스 2~3개를 고르고 `lib.mjs note <id>`로 핵심과 레이아웃·타이포·색·질감 수치를 읽는다. 수치는 그대로 옮기지 않고 **비율과 관계**(제목:본문 크기 비, 여백 리듬, 명도 차)로 옮긴다. 노트 본문과 `## 실측 수치`가 다르면 실측을 믿는다. "첫 화면 제목: 없음"은 큰 글자 대신 사진이나 영상이 첫 화면을 맡는다는 뜻이니 스크린샷으로 확인한다. 고른 노트에 실측 수치가 없거나 첫 줄에 "화면이 거의 안 그려짐"이 있고 브라우저 도구가 있으면, 그 사이트를 1440px로 열어 `SKILL_DIR/scripts/measure.js`를 한 번 실행하고 결과를 고치지 말고 그대로 노트 맨 아래 `## 실측 수치`에 `- `로 시작하는 줄로 넣는다. "아래쪽" 줄에 wheel-probe.js가 나오면 add-reference 4단계대로 휠 탐색도 잰다. 맞는 게 없으면 `/webcraft:add-reference`를 안내한다.

**3. 재료.** `system-designer`를 한 번 실행한다. 넘길 것: 요청 요약(한국어 페이지인지), 스타일 키, 레퍼런스 id들, 브랜드 색, `SKILL_DIR/scripts` 경로. 받을 것: 팔레트 2개, 글꼴 조합 2개, 모션, 대비 검사 명령. 그 명령을 메인이 한 번 실행하고, FAIL이 있으면 그 색만 고쳐 다시 실행한다.

**4. 방향 확인과 구도 스케치.** `SKILL_DIR/guide/report.md`를 읽고 방향과 **구도 스케치**(콘셉트 한 문장, 안정안과 과감안 두 가지의 첫 화면 구도와 시그니처 요소, 섹션별 틀, 기준 수치)를 함께 보여준다. **여기서 멈추고 확인을 기다린다.** 확인받으면 구도 스케치를 `design-log.md` 맨 위에 그대로 적는다.

**5. 구현.** 먼저 `SKILL_DIR/guide/anti-ai-look.md`를 읽고 디자인, 구조, 문구 모두 그 목록을 피한다. 스타일 카드의 **수치 토큰**을 `:root`에 넣고, `lib.mjs example <style>`이 있으면 한 번 받아 수치와 정밀함만 배운다. **배치는 따라 하지 않는다** (예와 같은 배치면 검수에서 큰 문제). 고른 레시피는 `lib.mjs recipe <이름...>` 한 번으로 받고, 서로 무관한 도구 호출은 한 메시지에 묶는다.
- 처음부터 한 번에 완성하려 하지 않는다. 뼈대(구조와 토큰)를 쓰고, 브라우저에서 첫 화면을 원본 배율로 보고, 구도 스케치와 비교해 다듬는다. 시그니처 요소는 따로 몇 번 고쳐 써도 된다. 다만 같은 파일을 한 줄씩 여러 번 고치기보다 한 번에 모아 고친다
- **구도 스케치를 설계도로 쓴다.** 첫 화면 배치, 섹션별 틀, 기준 수치를 그대로 지킨다. 시그니처 요소에 공을 가장 많이 들인다. 바꿔야 하면 이유를 `design-log.md`에 적는다
- 레퍼런스의 코드, 이미지, 문구를 가져오지 않는다
- **문구를 다 쓴 뒤 덜어낸다.** 섹션마다 제목과 한두 문장을 남기고, 지워도 뜻이 통하는 문장, 라벨, 주석을 지운다. 사용자가 긴 글을 원한 경우만 예외다
- 모션은 고른 레시피 코드를 바탕으로 값만 조정한다. 모든 모션에 `prefers-reduced-motion` 대체
- 글꼴은 확인받은 불러오는 코드와 `--font-*` 변수를 쓰고, **페이지 전체에** 적용한다. 폰트 파일을 내려받아 넣지 않는다
  ```css
  body { font-family: var(--font-body); }
  h1, h2, h3, h4 { font-family: var(--font-display); font-synthesis: none; } /* 굵기가 하나뿐인 제목 글꼴에 가짜 굵기가 덧칠되지 않게 */
  button, input, select, textarea, nav, label { font-family: var(--font-ui); }
  button, input, select, textarea { font-size: inherit; } /* 폼 요소는 글꼴을 물려받지 않는다 */
  ```
  숫자 강조에는 `var(--font-num)`. 요소마다 `font-family`를 따로 박지 않는다
- **파는 것이 앱이나 소프트웨어라 제품 화면을 보여 줘야 하면** `SKILL_DIR/guide/product-ui.md`를 읽고 따른다. 제품 화면은 자리표시로 두지 않는다
- 그 밖의 이미지는 자리표시: 팔레트 안의 단색이나 아주 옅은 톤 블록 + "사진 자리표시: <무엇이 들어갈지>" 글자. **풍경, 인물, 산과 달 같은 그림을 CSS·캔버스·SVG로 그려 넣지 않는다** (가짜 그림은 AI 티가 가장 많이 난다). 3D 텍스처도 같다. 375px과 1440px 모두 깨지지 않게
- 검수용으로 결과물 폴더에서 로컬 서버를 띄울 수 있으면 띄운다

**6. 검수와 수정.** 기본은 `critic`이 처음과 마지막에만 채점하고, 중간 확인은 메인이 `audit.js`로 한다 (최대 3회). "꼼꼼하게"면 정밀 모드. 순서, 멈추는 조건, `design-log.md` 형식은 `SKILL_DIR/guide/review.md`를 읽고 따른다.

**7. 마무리.** `SKILL_DIR/guide/report.md`의 마무리 항목을 알린다.
